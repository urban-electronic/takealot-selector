# 逐箱清单与 OMS 入仓单：装完箱子还能查出「第 3 箱里是什么」

日期：2026-10-22
基线：`d97b9a8515`

## 问题：箱子封上以后，内容只存在于记忆里

装完货之后，同一票货的几个箱子外观完全一样。想查「那批货里到底有没有某个 SKU」、
「客户说少了两件，是哪箱少的」、「上次那箱易碎品装的是什么」，只能靠回忆。

系统里其实已经有装箱单（`Shipment` / `ShipmentLine`），但它是**按 SKU 汇总**的形状：

```
9902348623136  皮革黑色包   3 箱 × 10 件
9902348621873  宝马后视镜盖 2 箱 × 5 件
```

它回答不了「第 3 箱里是什么」。而「第几箱」才是贴纸箱外面、能对着箱子找到的那个维度。

顺带发现一处半成品：装箱单 Excel 的 A 列（唛头）代码是
`'A': p.get('box_no') or (mark if i == 0 else '')`，**接口早就有逐行 `box_no`，
前端一直没传**，所以 A 列只有第一行有唛头，其余是空的。这条链路补完就成了逐箱清单。

## 做法：加一层「按箱」的记录，两种装法都覆盖

新表 `shipment_cartons`（一箱一条：序号、箱号、备注）+ `shipment_carton_items`
（箱内明细：SKU、品名、数量）。一箱多行 SKU 就是混装。

关键是**两种装法都不用增加操作**：

### 一箱一个 SKU：什么都不用填

装箱页填好「2 箱 × 10 件」之后点导出，后端 `_auto_cartons()` 直接展开：

```
C01 → 皮革黑色包 ×10
C02 → 皮革黑色包 ×10
C03 → 宝马后视镜盖 ×5
...
```

页面上也可以点「按 SKU 展开」先看一眼再改。这是最常见的情况，不能要求人手填。

### 混装：手动加箱

「+ 新建一箱」→ 逐行选产品填数量 →「这箱再加一个产品」。前端把整个箱列表随导出一起
提交，后端以提交的为准。

## 三道闸：箱内合计必须等于装箱单

逐箱清单和装箱单**必须是同一票货**。箱子里写 10 件、账上扣 12 件，比没有记录更糟 ——
箱唛印出去就是错的，而且没人会发现。所以：

1. **页面实时算**：`cartonTotals` 逐 SKU 比对「箱内合计」与「箱数 × 每箱件数」，
   对不上就在面板底下显示「宝马后视镜盖 箱内 20 / 装箱单 15」；
2. **导出前拦**：有差额直接不提交，提示「请先调整逐箱清单，或点『按 SKU 展开』重来」；
3. **后端再校验**（`_normalize_cartons`）：合计不符、箱里有不属于本单的 SKU、空箱，
   一律 400 并说清是第几箱。后端这道不能省 —— 前端可以绕过。

## 顺手修掉的：同一草稿重复导出会印错箱唛

导出时装箱单 Excel 是按**本次** payload 重新生成的，但 `ShipmentLine` 只在第一次导出时
写入。于是「填错数量 → 改 → 再导一次」会出现：Excel 上是新数量，库里还是旧数量。
如果箱清单也只写第一次，箱唛就会照着旧数据印 —— 这正是这个功能最不能出的错。

现在同一 `draft_key` 再导出时：

- `status = exported`（没扣库存）：明细与箱清单**整体按本次重写**，幂等；
- `status = confirmed`（已扣库存）：数量变了直接 409「已确认发货（库存已扣减），
  不能改数量；要改请先作废再重开」。数量没变则只重写箱清单（拆箱合箱不影响库存）。

明细里被删掉的 SKU 若已被库存分摊引用（`ShipmentAllocation`），同样 409，不静默删。


## 箱唛不是我们出的：OMS 自己打，而且明细就在上面

前后错了两次，最后是靠用户从 OMS 导出的 `a9e9d07e-…pdf`（入库单 `INH1501522`，
8 箱，9 页）定下来的。**真实箱唛**（102×102mm，热敏）：

```
KPL-海运                                    Box 3 of 8
─────────────────────────────────────────────────────
WH: 约堡仓                        PCS: 107
KPLDJ                             SKUs: 8
─────────────────────────────────────────────────────
INH1501522                        2026-10-23 00:10
[ 大条码 ]
                  INH1501522-003
┌──────────────────┬──────────────┐
│       SKU        │   单箱数量    │
│  9902348624409   │      16      │
│  9902388556586   │      31      │
└──────────────────┴──────────────┘
```

**关键事实：箱唛上本来就有「SKU / 单箱数量」那张表。** 箱子贴的纸已经说清
里面装了什么，所以「再印一张箱内明细贴」是纯重复劳动 —— 那一版已删除，
连同 100×100 的排版、降档、打印 portal 和对应用例一起。

第一版错在把箱唛当自研标签（100×70）；第二版错在 OMS 的箱唛之外又排了一张
明细贴。两次都是「没先看对方模板就自己设计」。

### 唯一真缺口：超过 5 行 SKU 时，第 2 页没有箱号

箱唛表格每行 21.5pt，表头在 154.6pt、5 行到 274.0pt 刚好贴到 289.1pt 页底。
第 6 行起会**另起一页**，而那一页只有表格，没有箱号、没有条码、没有单号 ——
`INH1501522` 第 3 箱（8 个 SKU）就印成了两页，第二页谁也认不出是哪箱。

所以不再自己补纸，改成**装的时候就提示**：逐箱清单里一箱超过 5 个 SKU 会挂一个
「6 个 SKU，超出箱唛 5 行」的标签，导出时提示条再点一次名。要么拆箱，要么自己
在第二页手写箱号 —— 由人决定，不由代码替人排版。

`MAX_SKUS_PER_BOX = 5` 前端（`Packing.tsx`）和后端（`services/inbound_excel.py`）
各有一份，值必须一致：前端管提示，后端管导出时点名。

## 真正该串的那一环：逐箱清单 → OMS 入仓模板

用户的流程是固定的四步：**东西做好 → 在 OMS 登记对应 SKU → 创建入库单 → 打印箱唛贴箱**。
第 2、3 步是重复劳动：装箱页已经知道「第几箱装了什么、各多少件」，却还要在 OMS
里再录一遍。

OMS 支持用 Excel 批量导入建入库单，模板就是 `backend/inbound_template.xlsx`：

| 列 | 含义 | 说明 |
|---|---|---|
| A `*标识号` | 箱子编号 | **相同的行 = 同一个箱子**，这是 OMS 认箱的唯一依据 |
| B `*箱子数量` | 1 | 一行一箱，恒为 1 |
| C `自定义箱号` | 留空 | 非必填，见下文「只写带 `*` 的列」 |
| I `*SKU` | 条码 | |
| J `*SKU数量/箱` | 这箱装几件 | |

用户手工维护的 `海运_ERP入仓模板_2026-10-07.xlsx` 就是这 19 行：标识号
`1,1,2,2,3,3,3,3,3,3,3,3,4,5,5,6,7,8,8` —— **一箱一组，同箱多 SKU 共用标识号**。

### 改之前是错的

旧实现按 `ShipmentLine` 出行、`enumerate` 递增标识号：

- 一票 2 箱 × 2 个 SKU → 生成 4 行、标识号 1/2/3/4，OMS 里变成 **4 个箱子**；
- 勾两票时每票的标识号都从 1 开始 → 两票的箱子在 OMS 里**并成一批**。

现在 `generate_inbound(boxes)` 收的是 `[(箱序, [(sku, 每箱数量), …]), …]`，
箱序由接口层跨单据连续累加（`len(boxes) + 1`），同一箱的多行共用箱序。

数据源换成 `shipment_cartons` / `shipment_carton_items`（逐箱清单），
没有逐箱记录的老单据才退回「一行一箱」。用真实 8 箱数据回放：
8 箱 / 19 行 / 235 件，标识号与用户手改的那份文件结构完全一致。

### 导出时把箱数、件数、超限箱带回前端

响应体是 xlsx，没法塞 JSON，所以走响应头 `X-Inbound-Summary`
（`json.dumps(..., ensure_ascii=True)`，中文转 `\uXXXX` 保证 header 只含 ASCII）：

```json
{"cartons": 8, "pieces": 235, "rows": 19,
 "overflow": [{"box_no": "INH1501522-003", "skus": 8, "overflow": 3}]}
```

跨域读自定义响应头要显式放行，`main.py` 的 `CORSMiddleware` 加了
`expose_headers=["X-Inbound-Summary"]`，否则前端 `res.headers.get()` 拿到 `null`，
提示语退回「N 张装箱单」。

## 事后查询

`GET /api/packing/cartons?date=2026-10-22` → 当天装了哪些箱；
`GET /api/packing/cartons?sku=9902348623136` → 这个 SKU 在哪几箱。

**两个「箱数」不是一回事，别混：**

- 每行的 `total` = **整票货的总箱数**，箱唛印「第 3 箱 / 共 5 箱」靠它。
  按 SKU 筛时它**不变**。
- 顶层的 `total_cartons` = **本次返回了多少箱**（`len(rows)`）。按 SKU 筛时会变小。

所以按 SKU 查时界面文案是「找到 2 箱装了 X（箱唛上的「共 N 箱」仍是整票总数）」，
不能写「共 2 箱」—— 那和行里的「共 5 箱」自相矛盾。

界面上是头部「查箱子」按钮：选日期查当天，或填 SKU 反查。结果按票分组
（同一趟货的箱排在一起），每行一箱，直接列出箱里装了什么、多少件。纯查询，
不再带勾选和重印 —— 箱唛由 OMS 打，重印去 OMS 重打。

### 导出之后：提示条直接给「导出 OMS 入仓模板」

没点「按 SKU 展开」就直接导出的人不少（后端会自动展开，Excel 一样是对的）。
那时前端草稿随即被清空、`cartons` 是空数组，最容易漏掉的正是「去 OMS 建入库单」这一步。

所以导出成功的提示条带一个「导出 OMS 入仓模板」按钮：点开入仓模板弹层，
**默认勾上刚导出的那一票**（列表按 `created_at` 倒序，第一条就是它）。
提示条上的按钮带 `for: <文案>`，别处 `setMsg` 换了文案按钮会自动消失。

### 两个踩过的坑

**① 弹层里给 `label` 写布局必须带 `.packing-modal` 前缀。**
`.packing-modal label { display: block }` 是 (0,2,0)，会压掉
`.carton-query-row { display: grid }` 的 (0,1,0)，整行退化成行内流 ——
箱号和「第 N 箱」粘在一起。`tsc` 和断言都发现不了，只有截图能看出来。
现在查询行改成 `<div>`，不再依赖 `label`，但弹层里其它 `label` 仍受这条约束。

**② fixture 不能比后端「更宽容」。**
第一版 fixture 把 `total_cartons` 写死成 5，而真实后端返回 `len(rows)` ——
按 SKU 筛时只有 2。于是用例断言「共 5 箱」通过，真实环境却显示
「共 2 箱（…仍是整票总数）」，前后打架。fixture 现在返回 `len(rows)`。

## 装箱单也跟着按箱展开（2026-10-23）

`packing_template.xlsx`（鲲鹏物流装箱单）的 **A 列标题就是「箱唛」**，但导出时一直
填的是唛头 `CK-01`，箱唛号没进去。而用户手上那份 `KPLDJ_海运装箱单_8箱.xlsx`
是按箱展开的：

| A 箱唛 | B SKU | C 品名 | D 箱数 | E 内件数量 |
|---|---|---|---|---|
| `INH1501522-001` | 9902367061100 | … | 1 | 17 |
| （空） | 9902388560071 | … | （空） | 6 |
| `INH1501522-002` | 9902391033760 | … | 1 | 10 |

所以 `px.generate()` 加了 `boxes` 参数：给了就按箱展开，没给就还是按 SKU 汇总
（老调用方不受影响）。`export_excel` 现在把 `cartons_plan` 传下去，于是
**装箱单和 OMS 入仓文件说的是同一件事**，箱唛号两边能对上。

两条不能违反的规则：

- **箱唛号只写在每箱第一行。** 每行都写，物流会以为有 8 个箱子。
- **箱数只在每箱第一行写 1。** 每行都写 1，箱数会被累加成 8 箱。

`dimension` 也从 `len(items)` 改成 `len(lines)` —— 按箱展开后行数变多，
还用 items 的长度会让 Excel 认为表格只有几行。

### 同批修掉的三个界面问题

跑真机截图才看出来的（`tsc` 和断言都发现不了）：

1. **箱号输入框被截成 `INH1501522-`**。宽度按 `C01` 定的 96px，填了入库单号就放不下
   13 个字符 —— 而这串号是这箱唯一的凭据。改成 150px + `tabular-nums`。
2. **超限提示挤在「第 N 箱 / 共 M 箱」旁边**，把删除按钮顶到下一行。改成整行独占。
3. **窄屏 360px 下「第 N 箱」和 × 一上一下错开**。给 seq 和删除按钮分别定 `order`，
   让它们待在同一行末尾；箱号输入框在窄屏改成 `width: 100%` 跟格子走。

### 入仓文件只写带 `*` 的列

模板里只有 A 标识号、B 箱子数量、I SKU、J SKU数量/箱 带 `*`。C 列「自定义箱号」
**留空** —— 标识号已经说明是哪个箱子，再填一遍纯属重复；而且填进去的号
（`01`、`02`）跟 OMS 生成的箱唛号（`INH1501522-001`）不是一回事，放在一起容易看混。

这一列前后改过三次：文本 `"01"` → 数字 `1、2、3` → 留空。教训是别在用户
没要求的列上做决定，OMS 只认带 `*` 的那四列。
