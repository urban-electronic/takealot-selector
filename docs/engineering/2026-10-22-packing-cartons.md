# 逐箱清单与箱内明细贴：装完箱子还能查出「第 3 箱里是什么」

日期：2026-10-22
基线：`d97b9a8515`

## 问题：箱子封上以后，内容只存在于记忆里

装完货之后，同一票货的几个箱子外观完全一样。想查「那批货里到底有没有某个 SKU」、
「客户说少了两件，是哪箱少的」、「上次那箱易碎品装的是什么」，只能靠回忆。

系统里其实已经有装箱单（`Shipment` / `ShipmentLine`），但它是**按 SKU 汇总**的形状：

```
9902348623136  皮革黑色包   3 箱 × 10 件
9902348621873  宝马后视镜盖 2 箱 × 5 件
```

它回答不了「第 3 箱里是什么」。而「第几箱」才是贴纸箱外面、能对着箱子找到的那个维度。

顺带发现一处半成品：装箱单 Excel 的 A 列（唛头）代码是
`'A': p.get('box_no') or (mark if i == 0 else '')`，**接口早就有逐行 `box_no`，
前端一直没传**，所以 A 列只有第一行有唛头，其余是空的。这条链路补完就成了逐箱清单。

## 做法：加一层「按箱」的记录，两种装法都覆盖

新表 `shipment_cartons`（一箱一条：序号、箱号、备注）+ `shipment_carton_items`
（箱内明细：SKU、品名、数量）。一箱多行 SKU 就是混装。

关键是**两种装法都不用增加操作**：

### 一箱一个 SKU：什么都不用填

装箱页填好「2 箱 × 10 件」之后点导出，后端 `_auto_cartons()` 直接展开：

```
C01 → 皮革黑色包 ×10
C02 → 皮革黑色包 ×10
C03 → 宝马后视镜盖 ×5
...
```

页面上也可以点「按 SKU 展开」先看一眼再改。这是最常见的情况，不能要求人手填。

### 混装：手动加箱

「+ 新建一箱」→ 逐行选产品填数量 →「这箱再加一个产品」。前端把整个箱列表随导出一起
提交，后端以提交的为准。

## 三道闸：箱内合计必须等于装箱单

逐箱清单和装箱单**必须是同一票货**。箱子里写 10 件、账上扣 12 件，比没有记录更糟 ——
箱唛印出去就是错的，而且没人会发现。所以：

1. **页面实时算**：`cartonTotals` 逐 SKU 比对「箱内合计」与「箱数 × 每箱件数」，
   对不上就在面板底下显示「宝马后视镜盖 箱内 20 / 装箱单 15」；
2. **导出前拦**：有差额直接不提交，提示「请先调整逐箱清单，或点『按 SKU 展开』重来」；
3. **后端再校验**（`_normalize_cartons`）：合计不符、箱里有不属于本单的 SKU、空箱，
   一律 400 并说清是第几箱。后端这道不能省 —— 前端可以绕过。

## 顺手修掉的：同一草稿重复导出会印错箱唛

导出时装箱单 Excel 是按**本次** payload 重新生成的，但 `ShipmentLine` 只在第一次导出时
写入。于是「填错数量 → 改 → 再导一次」会出现：Excel 上是新数量，库里还是旧数量。
如果箱清单也只写第一次，箱唛就会照着旧数据印 —— 这正是这个功能最不能出的错。

现在同一 `draft_key` 再导出时：

- `status = exported`（没扣库存）：明细与箱清单**整体按本次重写**，幂等；
- `status = confirmed`（已扣库存）：数量变了直接 409「已确认发货（库存已扣减），
  不能改数量；要改请先作废再重开」。数量没变则只重写箱清单（拆箱合箱不影响库存）。

明细里被删掉的 SKU 若已被库存分摊引用（`ShipmentAllocation`），同样 409，不静默删。

## 箱唛不是我们生成的：先分清两张纸

第一版把「箱唛」理解成我们自己设计的标签，是错的。看过 OMS 导出的
`KPLDJ_海运装箱单_8箱.xlsx`（鲲鹏物流装箱单模板，第 1 列标题就叫「箱唛」）
和模板里嵌的「箱唛示例图」之后，实际是两张不同的纸：

| | 谁生成 | 长什么样 | 尺寸 |
|---|---|---|---|
| **箱唛** | OMS（JF WMS「入库单管理」） | `Inbound` / `Box 3 of 8` / `WH: 约堡仓` / `PCS` / `SKUs` / 单号+时间 / 大条码 / **箱唛号** | 100×100 热敏 |
| **箱内明细贴**（本系统） | 我们 | 箱唛号 / `第 3 箱 / 共 8 箱` / 品名 + SKU + ×数量 | 100×100 热敏 |

**箱唛号**是两张纸唯一能对上的凭据，格式固定为 `{入库单号}-{3 位箱序}`，
例如 `INH1501522-003`。OMS 的箱唛把它印在条码下方。

所以本系统的正确职责不是「生成箱唛」，而是：
1. 记下每箱装了什么（逐箱清单）；
2. 用**同一个箱唛号**把明细贴印出来，贴在箱子另一面；
3. 事后按箱唛号能反查这箱是什么。

装箱页「逐箱清单」里填 **OMS 入库单号**（如 `INH1501522`），箱号立刻变成
`INH1501522-001`、`-002`…，与 OMS 打出来的箱唛逐箱对应；不填就退回 `C01`、`C02`。
改入库单号时已有箱的箱号会跟着重算，不用逐箱手改。

### 尺寸与排版

`@page { size: 100mm 100mm }`，一张一页 —— 尺寸照用户的热敏纸来，不是 A4，也不是 100×70。

用 HTML 打印而不是生成 PDF：明细必须能印**中文品名**，而 `src/utils/labelPdf.ts`
那个零依赖 PDF 生成器只支持 ASCII（中文变 `?`，见 `2026-10-22-product-labels.md`）。

**必须印「第几箱 / 共几箱」**：一堆箱子堆在一起时，光看箱号分不出哪箱是今天的、
还差几箱没装。

**箱唛号绝不能被折断。** 17pt 时 `INH1501522-003` 刚好一行；给 20pt 会折成
`INH1501522-` + `003` 两行 —— 这串号是唯一凭据，断了就失去意义。所以
`.carton-label-no { white-space: nowrap }`，字号上限 17pt。

### 混装箱：按行数降档，一行都不能少

100×100 里留给明细只有约 58mm。真实数据里第 3 箱混装 **8 个 SKU**，
按大字号需要 323px 而只有 194px —— **后 4 行会被裁掉**，贴上去等于这箱白记。

按行数分三档（`labelClass()` 挂 `is-compact` / `is-dense`）：

| 行数 | 档位 | 品名 | SKU | 数量 | 排布 |
|---|---|---|---|---|---|
| 1–3 | 默认 | 11pt | 8pt（品名下） | 16pt | 两行 |
| 4–6 | `is-compact` | 9.5pt | 7pt | 13pt | 两行 |
| ≥7 | `is-dense` | 8pt | 6pt（**品名右侧**） | 10.5pt | 一行 |

dense 档把 SKU 挪到品名右边同一行，省掉每行的第二行高度 —— 这是 8 行能塞进
100×100 的关键。实测 8 行 overflow = 0。

用例里钉了「每张明细贴 `scrollHeight - clientHeight ≤ 0`」，
字号一改就会被抓到。

### 两个踩过的坑

**① 打印时不能用 `visibility: hidden` 隐藏应用。**
第一版用 `body * { visibility: hidden }` 只留标签，结果 5 张印出 **14 页** ——
`visibility` 保留布局高度，应用那一长条页面照样参与分页。改成 `display: none` 后是 5 页。
但 `display: none` 会把标签自己一起藏掉（它在 `#root` 里），所以用 `createPortal`
挂到 `document.body`，打印时隐藏 `body > *:not(.carton-print-overlay)`。

**② 模态层级要对齐项目的 1200。**
第一版给 `z-index: 60`，顶部导航是 `z-index: 100`，直接把工具栏盖住 —— 打印和关闭
按钮点不到。项目里 `.app-modal-backdrop` / `.seller-assist-backdrop` 都用 1200，照抄。

## 事后查询

`GET /api/packing/cartons?date=2026-10-22` → 当天装了哪些箱；
`GET /api/packing/cartons?sku=9902348623136` → 这个 SKU 在哪几箱。

**两个「箱数」不是一回事，别混：**

- 每行的 `total` = **整票货的总箱数**，箱唛印「第 3 箱 / 共 5 箱」靠它。
  按 SKU 筛时它**不变**，否则箱唛会印成「共 3 箱」。
- 顶层的 `total_cartons` = **本次返回了多少箱**（`len(rows)`）。按 SKU 筛时会变小。

所以按 SKU 查时界面文案是「找到 2 箱装了 X（箱唛上的「共 N 箱」仍是整票总数）」，
不能写「共 2 箱」—— 那和行里的「共 5 箱」自相矛盾。

界面上是头部「查箱子」按钮：选日期查当天，或填 SKU 反查。结果按票分组
（同一趟货的箱排在一起），每行一箱，直接列出箱里装了什么、多少件。

### 导出之后怎么印箱唛

没点「按 SKU 展开」就直接导出的人不少（后端会自动展开，Excel 一样是对的）。
但那时前端草稿随即被清空，`cartons` 是空数组 ——「打印箱唛」按钮是灰的，
用户会以为这票货印不了箱唛。

所以导出成功的提示条上带一个「去印箱唛」按钮，点开就是查箱子 → 当天 → 5 箱，
勾「全选本票」直接重印。提示条上的按钮带 `for: <文案>`，
别处 `setMsg` 换了文案按钮会自动消失，不会留下指向旧动作的按钮。

**重印不重排。** 从记录里勾第 3、4 箱重印，箱唛上必须还是「第 3 箱 / 共 5 箱」
「第 4 箱 / 共 5 箱」。如果按「本次选中几张」重新编号，同一只箱子就会印出两个箱号，
贴上去以后谁也说不清哪个是对的。重印走独立的 portal（`reprintRows`），
与草稿箱唛互斥，避免两个 overlay 一起进打印流。

### 第三个坑：`.packing-modal label` 会把 grid 压成行内流

查询结果每行是 `<label class="carton-query-row">`（点整行就能勾选），
样式写成 `display: grid`。第一版直接写 `.carton-query-row { display: grid }`，
特异性 (0,1,0)；而 `.packing-modal label { display: block }` 是 (0,2,0) ——
grid 被压回 block，箱号 `C01` 和「第 1 箱」粘成 `C01第 1 箱`，勾选框也贴着文字。
截图一眼就能看出来，但 `tsc` 和断言都发现不了。

修法是选择器统一加 `.packing-modal` 前缀（`.packing-modal .carton-query-row`），
并显式 `margin-bottom: 0` 抵消 `.packing-modal label` 的 4px。
**在这个弹层里给 `label` 写布局，必须带前缀。**

### 第四个坑：fixture 比后端「更宽容」，把文案矛盾遮住了

第一版 fixture 里 `total_cartons` 写死成 5，而真实后端返回的是 `len(rows)` ——
按 SKU 筛时只有 2。于是用例断言「共 5 箱」通过，真实环境却显示
「共 2 箱（…「共 N 箱」仍是整票总数）」，前后打架。

修法两条：文案改成「找到 N 箱装了 X」；fixture 改成 `len(rows)` 忠实于后端。
**fixture 不能比真实接口更宽松**，否则用例只是证明「fixture 自己一致」。
