# 站外货源：详情页展示 1688 与 Takealot 上的外部商品

日期：2026-10-29
状态：已实现（后端 + 前端 + 守卫）

## 为什么做这个

详情页原来只有一块「同类商品 / 配套周边」，数据来自**自家商品库**。对选品来说这不够：
库里只有自己上架过的东西，回答不了两个最实际的问题——

- 这件商品在 1688 上进货价大概多少？
- 同类在 Takealot 上别人卖多少钱？

这两个问题的答案都不在自己仓库里，所以单独做一块「站外货源」，
把站外看到的商品登记进来，按关键词挂到对应商品下面。

## 先说清楚：不做实时抓取

实测两个平台的搜索接口，都拿不到结构化结果：

| 目标 | 结果 |
|---|---|
| `www.takealot.com/all?q=…`（搜索页） | 403，Cloudflare 返回 `Just a moment...` 人机校验页 |
| `api.takealot.com/rest/v-1-9-0/searches?q=…` | 403，同上 |
| 单商品页（`/xxx/PLID…`）普通请求 | 403，同上 |
| `s.1688.com/selloffer/offer_search.htm?keywords=…` | 200，但只返回 5KB 跳转壳（windvane） |

真实浏览器（Playwright，未做指纹伪装）打开 Takealot 搜索页同样停在
`Performing security verification`。**绕过这些校验不是本项目要做的事**，
所以这里的方案是「登记 + 关键词匹配」，价格以链接里的实际页面为准。

界面上把这件事写明了（「两个平台都不做实时抓取……数据靠登记」），
避免有人以为价格是实时同步的。

## 数据结构

表 `external_offers`（`backend/models.py:ExternalOffer`）：

| 字段 | 说明 |
|---|---|
| `platform` | `1688` / `takealot` |
| `url` | 必填，域名必须与平台一致 |
| `title` / `title_cn` | 原文标题 / 中文标题 |
| `price` + `currency` | **成对存**：1688 是人民币批发价、Takealot 是兰特零售价 |
| `moq` | 起订量，只有 1688 才有 |
| `keywords` | 逗号分隔，决定挂到哪些商品下面 |
| `usage` / `scenario` / `reason` | 用途 / 适用场景 / 选择理由 |
| `is_active` | 下线用，不物理删除 |

`price` 与 `currency` 必须成对：混成一个数字，界面上会把 R 当成 ¥ 直接比大小。

## 匹配与排序

`backend/services/external_offers.py`：

- **英文关键词整词匹配**（复用 `product_recommendation.contains_phrase`）：
  `cap` 不会命中 `capacity`、`clip` 不会命中 `clipper`。这两个坑在库内推荐里已经踩过两次。
- **中文关键词子串匹配**：中文没有词边界，只能按子串。
- **没命中就不展示**：`if not hits: unscored += 1; continue`。宁可版面空着，
  也不为了填满把不相干的站外商品塞进来。
- **排序**：命中关键词数 → 有价格优先 → 价格低优先 → 录入时间。
  没有价格的排在后面但仍展示（1688 的批发价经常要问客服，缺价格不代表没用）。
- **每栏上限**：默认 8、硬上限 20，服务层用 `max(0, min(limit, MAX_LIMIT))` 夹紧。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/external-offers` | 列表（管理用，可按平台/关键词过滤） |
| POST | `/api/external-offers` | 新增 |
| PATCH | `/api/external-offers/{id}` | 修改 |
| DELETE | `/api/external-offers/{id}` | 下线（`is_active=False`，不物理删） |
| GET | `/api/external-offers/for-product/{product_id}` | 详情页用，分两栏返回 |

校验点：

- **域名白名单**：`1688.com` / `takealot.com`，认子域（`m.takealot.com`）。
  粘错平台在这里就挡掉，免得详情页出现一条点开是错的平台的「货源」。
- **scheme 只放 http/https**：这个字段最终渲染成可点链接，
  `javascript:` 混进来就是一个可执行的注入点。
- **同链接去重**：同一店铺内 URL 唯一，重复登记回 409。
- **`price <= 0` 落成空**：1688 上「价格待议」常被填成 0，留着会在界面上显示 ¥0。

## 展示位置

产品详情页**最后一块**（「同类商品 / 配套周边」之后）：

- 两栏：`1688 货源`（采购侧 · 人民币批发价）/ `Takealot 同类`（零售侧 · 兰特售价）；
- 每张卡片显示平台徽标、标题、价格、起订量、用途、场景、理由，
  以及**「为什么挂在这里」**——命中的具体关键词；
- 底部展示已登记数 / 命中数 / 未命中数 / 匹配规则 / 排序 / 每栏上限；
- 底部两个**可编辑**的搜索词输入框 + 「去 1688 搜」「去 Takealot 搜」两个外跳入口。
  默认值取商品中文名（1688）/ 英文名（Takealot），但**不锁死**——
  真实库里很多商品的中文名就是「假发」这种大类词，拿它直接搜会出来一整屏不相干的东西，
  所以默认值只是起点，用户可以改成「发网」「假发支架」再点；
- 读失败降级成这一块的提示，并**与「没有货源」区分开**——
  一个是网络/服务端问题，一个是真的没录过，这两件事在处理上完全不同。

## 桌面端（本地数据源）

桌面端本地库没有这张表，也没有对应 Rust 命令（加命令要重新编译客户端，
且会变成两份数据各自维护）。所以 `src/api.ts` 里的同名函数**转调 remoteApi**，
数据只有服务端一份。桌面端连不上服务端时抛错、界面降级成「暂时读不到」。

## 已知限制

- **不做实时抓取**：价格是登记时的，会过期。要更新只能手动改。
- **品牌名会被当品类词**：和库内推荐同一个问题，关键词里写了品牌词（`zenty`、`tapo`），
  它就会把同品牌的其它品类也挂过来。登记时别用品牌词当关键词。
- **跨店不共享**：`store_id` 隔离，多店铺需要各录一份。
- **数据靠人录**：没有自动发现能力——这是「不做反风控绕过」的直接代价，不是遗漏。
