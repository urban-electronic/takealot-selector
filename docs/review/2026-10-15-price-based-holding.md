# 按原PricePilot价格逻辑复核本店报价

用户22:39明确要求按原程序比较和确认自己的价格。基于main90b34e9，原逻辑依据Mac实测报告888d166；不要求用户再次提供密钥或安装采集器。

## 价格推定与身份分别记录

1. 有效Buybox报价与本店任务售价相同：推定持有，记录task_snapshot及领取时点；不声称每次同价均调用实时官方接口。原程序同样首先按myPrice比较。
2. 不同价：采集成功正常入库，再对原offer的官方Seller API GET核对当前selling_price及SKU。若API最新价与Buybox相同，改为推定持有；否则推定未持有。此前已推定持有时，需要连续两轮有效异价核验才转失去，失败不计轮次。
3. 云端采集也执行相同推定；异价时在页面读取后再次GET，而不是只用导航前的本店价。
4. 新字段price_ownership含state/holding、对照价格/来源/时点、losing_rounds，identity_verified始终false；不写holdingBuyboxVerified，不把原程序的同价判据冒充可靠卖家身份。
5. 历史price_matches_buybox仅展示“历史同价·推定持有”，历史异价同理；不补造price_ownership/核验时间，不更新旧报价成功时间。

未复制原程序“无权威售价、单卡也当本店”的兜底；没有足够售价证据就显示核验未完成。也未用人工配置卖家名/同名或客户端holdingBuybox直接确认身份。原有变体/验证页/双读/库存/租约边界保留。

## 后端执行和并发边界

- 本机/扩展只在有效成功CAS入库后添加FastAPI响应后任务，报价接口不等待实时API核验；原successful/processed含义不变。
- 最多同时两批，每批最多20条、HTTP客户端5秒超时（每项），密钥仅由现有服务端配置按正常程序读取。没有凭据输出，也不扩展采集器权限。
- 饱和/重启可能使待核验状态保留到下一次有效轮次；不是自动恢复采集或永久核验队列，不承诺每条都即时完成。核验量与网络状态仍需实际运行观察。
- API异常、配置缺失、SKU不符：仅price_ownership标为verification_failed，保留报价和原成功时间。异常原文不写状态。
- 核验前和落库时都检查确切状态值；暂停、配置变化、新报价覆盖后旧检查不能回写。仅更新推定字段，不更新行情时间、快照、本店售价或真实平台价格。
- 调价继续使用原有保护；价格推定本身不满足holdingBuyboxVerified，不开启任何规则。可靠身份任务WB-BUYBOX-IDENTITY-01仍单独跟进。
